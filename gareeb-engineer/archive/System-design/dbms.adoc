**1st Normal Form (1NF)**: A relation is in 1NF if it contains only atomic (indivisible) values. This means that each column should contain only one value, and there should be no repeating groups or arrays.

Problem solved by 1NF: It eliminates duplicate columns from the same table and creates separate tables for each group of related data, which helps in reducing data redundancy and improving data integrity.

**2nd Normal Form (2NF)**: A relation is in 2NF if it is in 1NF and all non-key attributes are fully functionally dependent on the primary key. This means that there should be no partial dependency, where a non-key attribute depends on only a part of the primary key.

Problem solved by 2NF: It eliminates partial dependencies, which helps in reducing data redundancy and improving data integrity. It ensures that each non-key attribute is associated with the entire primary key, rather than just a part of it.

**3rd Normal Form (3NF)**: A relation is in 3NF if it is in 2NF and there are no transitive dependencies. This means that non-key attributes should not depend on other non-key attributes. In other words, every non-key attribute should depend only on the primary key.

Problem solved by 3NF: It eliminates transitive dependencies, which helps in reducing data redundancy and improving data integrity. It ensures that non-key attributes are only dependent on the primary key, not on other non-key attributes.

BCNF (Boyce-Codd Normal Form): A relation is in BCNF if it is in 3NF and for every functional dependency, the left-hand side is a superkey. This means that every determinant must be a candidate key.



definitons:

Prime atribute: An attribute that is part of a candidate key.

Super key: A set of attributes that can uniquely identify a tuple in a relation. It may contain additional attributes that are not necessary for uniqueness.

Notes:


to check normalization: alpha -> beta (alpha determines beta)

for BCNF: alpha -> beta (alpha is a candidate key)

for 3NF: alpha -> beta (alpha is a super key or beta is a prime attribute)

for 2NF: alpha -> beta (alpha is a part of the primary key and beta is a non-prime attribute)


example:
Consider a relation R with attributes (A, B, C, D, E, F) and the following functional dependencies:
1. A -> BCDEF
2. BC -> ADEF
3. DEF -> ABC

Candidate keys: A, BC, DEF

1NF: The relation R is in 1NF because all attributes contain atomic values.
2NF: The relation R is in 2NF because there are no partial dependencies. All non-key attributes are fully functionally dependent on the primary key (A, BC, DEF).
3NF: The relation R is in 3NF because there are no transitive dependencies. All non-key attributes depend only on the primary key and not on other non-key attributes.
BCNF: The relation R is in BCNF because for every functional dependency, the left-hand side is a candidate key (A, BC, DEF).
