== Introduction

Multithreading is the ability of a program to execute multiple threads concurrently.

A thread is the smallest unit of execution managed by the JVM.

Benefits:

* Better CPU utilization
* Improved application responsiveness
* Parallel task execution
* Scalability for server applications

Example Use Cases:

* Web servers handling multiple requests
* File processing
* Database operations
* Background jobs
* Microservices
* Messaging systems

== Thread Basics

A thread represents an independent path of execution.

Every Java application starts with a main thread.

[source,java]
----
public static void main(String[] args) {
    System.out.println(Thread.currentThread().getName());
}
----

Output:

[source,text]
----
main
----

---

== Thread Creation

=== Using Thread Class

[source,java]
----
class MyThread extends Thread {

    @Override
    public void run() {
        System.out.println("Thread running");
    }
}

public class Demo {
    public static void main(String[] args) {

        MyThread thread = new MyThread();
        thread.start();
    }
}
----

Use Case:

* Small demos
* Learning purposes

Not recommended for production code.

---

=== Using Runnable Interface

[source,java]
----
class Task implements Runnable {

    @Override
    public void run() {
        System.out.println("Executing task");
    }
}
----

[source,java]
----
Thread thread = new Thread(new Task());
thread.start();
----

Advantages:

* Better design
* Supports inheritance of another class

Use Cases:

* Web applications
* Enterprise applications
* Spring Boot services

---

=== Using Lambda (Java 8+)

[source,java]
----
Thread thread =
        new Thread(() ->
                System.out.println("Task running"));

thread.start();
----

Use Cases:

* Quick background tasks
* Modern Java applications

---

== Runnable Interface

Package:

[source,java]
----
java.lang
----

Definition:

[source,java]
----
@FunctionalInterface
public interface Runnable {

    void run();
}
----

Characteristics:

* Functional Interface
* No return value
* Cannot throw checked exceptions

Use Cases:

* Logging
* Email sending
* Background processing

---

== Callable Interface

Package:

[source,java]
----
java.util.concurrent
----

Definition:

[source,java]
----
public interface Callable<V> {

    V call() throws Exception;
}
----

Advantages over Runnable:

* Returns a value
* Can throw checked exceptions

Example:

[source,java]
----
Callable<Integer> task = () -> 100;
----

Use Cases:

* Database queries
* API calls
* Calculations

=== NEW

[source,java]
----
Thread t = new Thread();
----

Thread object exists.

---

=== RUNNABLE

[source,java]
----

----

Ready to run.

---

=== RUNNING

CPU schedules thread execution.

---

=== BLOCKED / WAITING

Thread waits for:

* sleep()
* join()
* I/O
* lock acquisition

---

=== TERMINATED

run() method completed.

== Synchronization

Used to prevent race conditions.

Problem:

[source,java]
----
count++;
----

Actually:

[source,text]
----
Read
Modify
Write
----

Multiple threads can interfere.

---

== synchronized

[source,java]
----
public synchronized void increment() {
    count++;
}
----

Advantages:

* Simple
* Built into JVM

Use Cases:

* Shared counters
* Shared resources

---

== Common Problems

=== Race Condition

Multiple threads modify shared state simultaneously.

Example:

[source,text]
----
Expected: 2
Actual: 1
----

Solution:

* synchronized
* Lock
* AtomicInteger

---

=== Deadlock

Two threads waiting forever.

Example:

[source,text]
----
Thread1 -> Lock A -> Lock B
Thread2 -> Lock B -> Lock A
----

Solution:

* Consistent lock ordering

---

=== Starvation

Thread never gets CPU time.

Solution:

* Fair locks
* Better scheduling

---

=== Livelock

Threads keep reacting to each other without progress.

Solution:

* Retry strategies
* Backoff mechanisms

== Interview Questions

start():

* Creates new thread

run():

* Executes in current thread

---

=== Runnable vs Callable

Runnable:

* No result

Callable:

* Returns result

---

=== synchronized vs Lock

synchronized:

* Simpler

Lock:

* More flexible

---

=== volatile vs synchronized

volatile:

* Visibility only

synchronized:

* Visibility + Mutual Exclusion

---

=== Future vs CompletableFuture

Future:

* Basic async result

CompletableFuture:

* Async pipelines and chaining
